# ADR 0001. Разбиение монолита по швам

Дата: 2026-11-15 · Статус: принято

## Контекст

`app/main.py` вырос до 1730 строк и совмещал HTTP-слой, правила чата, очередь,
синтез, Twitch API, работу с голосами и загрузками. Файл менялся в 11 из 20
последних коммитов. Правка одной части задевала соседние: добавление команды
в чате требовало держать в голове весь файл, а неисправность синтеза могла
сломать разбор HTTP-запроса.

## Решение

Разделяем **по ответственности, а не по размеру файла**. Каждый модуль отвечает
за одно решение и получает состояние явно. Порядок шагов выбран так, чтобы
чем дороже код, тем позже он трогается:

1. Правила чата → `app/chat_rules.py` (чистая функция `decide`).
2. HTTP-слой → `app/api.py` (сборка маршрутов `build_routes(state)`).
3. Настройки → `app/settings.py` (класс `Settings`).
4. Разрыв цикла импортов `textproc ↔ emotes`.
5. Очередь → `app/queue.py`.
6. Синтез → `app/synthesis.py`.

Каждый шаг — отдельный коммит без изменения поведения.

## Почему плоский `app/`, а не пакеты `api/`, `core/`, `tts/`

Пакеты из технического задания разложили бы 18 файлов по 7 каталогам, часть
из которых осталась бы пустой. Импорт внутри пакета меняется на относительный,
а flat-импорты (`from engine import ...`) работают одинаково в любой раскладке.
Плоская структура дешевле в поддержке и даёт ту же изоляцию.

## Последствия

* Состояние передаётся явно — модули не читают чужие глобальные переменные.
* Появились золотые слепки: поведение проверяется сравнением, а не на глаз.
* Требуется дисциплина: новый модуль сначала получает тест и слепок.
