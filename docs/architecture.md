# Архитектура TwitchTTS

Краткая карта модулей, процессов и потоков данных.

```
        браузер / OBS
              |  HTTP + WebAudio
              v
     +----------------------------+       +-----------------------+
     |  app/main.py (Starlette) |       |  app/api.py           |
     |  порт 8765               |  HTTP |  - страницы, /api/*   |
     |  - состояние приложения  | ----> |  - поток /events      |
     |  - очередь озвучки       |       |  - отдача /audio      |
     |  - пул потоков синтеза   |       +-----------------------+
     +---+--------+--------+----+
         |        |        |
   XTTS  |   RVC  |   CosyVoice 3
   поток |  поток |   отдельный процесс
         |        |
   app/engine.py  app/rvc.py      app/cosyvoice.py
         |        |        |
    TTS v2   Applio    app/cosyvoice_worker.py
   (venv)    (env)     (окружение CosyVoice)
```

## Процессы

| Процесс | Где живёт | Как общается |
|---|---|---|
| Основной сервер | `venv/Scripts/python.exe app/main.py` | HTTP |
| RVC-воркер | `Applio/env/python.exe app/rvc_worker.py` | построчно через stdin/stdout, префикс `@@RVC@@` |
| CosyVoice-воркер | `cosyvoice/env/python.exe app/cosyvoice_worker.py` | построчно через stdin/stdout, префикс `@@CV@@` |
| Обучение RVC | внутри Applio | отдельный процесс, прогресс читается из лога |

Воркеры живут в **своих** окружениях: у XTTS, RVC и CosyVoice несовместимые наборы
зависимостей и версии PyTorch. Поэтому общение с ними — простой текстовый протокол
(одна строка JSON на запрос, одна строка JSON на ответ), а не импорт через Python API.

XTTS — единственный движок, который импортируется напрямую (`app/engine.py`),
поэтому он выполняется в пуле потоков основного процесса.

## Модули

### `app/main.py`
Сервер и оркестратор: состояние приложения, синтез, Twitch API.

* `App` — состояние и правила жизненного цикла: настройки, голоса, движки,
  очередь, `on_chat()`, `_synth()` (общий путь синтеза: очистка текста → выбор
  движка → озвучка → запись файла в `data/cache` → отдача по `/audio`).
* Очередь озвучки живёт в `app/speak_queue.py`: App только собирает
  задание и передаёт его очереди.
* `routes = api.build_routes(app_state)` — маршруты собирает модуль HTTP-слоя,
  состояние передаётся ему явно.
* В модуле есть собственный логгер `log` (`logging.getLogger("main")`).
  Раньше его не было: `log.exception()` в воркере ронял очередь озвучки при
  любой ошибке синтеза.

Правила чата вынесены в `app/chat_rules.py`, HTTP-слой — в `app/api.py`,
очередь — в `app/speak_queue.py`. Синтез пока в этом же файле — порядок
разбиения описан в разделе «Разделение `app/main.py`».

### `app/api.py`
HTTP-слой: страницы, эндпоинты, поток событий, отдача звука.

* Шов: `build_routes(state)` — маршруты собираются под конкретное состояние,
  обработчики получают его первым аргументом. Глобальных переменных нет:
  модуль не знает про `main.py` и не импортирует его.
* `ok()` / `fail()` — единый формат ответа (`{"ok": true, ...}` / `{"ok": false, "error": ...}`).
* `page_*` — страницы (`/`, `/chat`, `/voices`, `/overlay`, `/poll`, `/player`, `/brb`).
* `api_*` — эндпоинты: состояние, настройки, подключение, очередь, озвучка,
  голоса, обучение RVC, CosyVoice.
* `events` — поток событий (SSE) для браузера: чат, статусы, реплики озвучки.
* `audio` — отдача готового wav из `data/cache`.
* Отладочный маршрут `/api/debug/chat` включается переменной окружения
  `TTS_DEBUG_CHAT=1`.
* Проверяется таблицей маршрутов и сверкой с золотым слепком
  `tools/golden_api.json` (37 маршрутов, 25 запросов) — `tools/test_api.py`.

### Связность модулей
* `tools/test_imports.py` строит граф импортов `app/` (включая отложенные
  импорты внутри функций) и требует, чтобы циклов не было.
* Там же проверка, что ни один модуль не использует имя, которое нигде не
  объявлено: такие ошибки всплывают только в рантайме.
* `tools/test_chat_live.py` - сквозная проверка чата через HTTP: команда из
  чата доходит до обработчика без исключения, бот отвечает.

### `app/paths.py`
Общие пути: `APP_DIR`, `ROOT`, `DATA`, `CACHE`, `TMP`, `WEB`, `MAX_UPLOAD`.
Вынесены, чтобы `main.py` и `api.py` смотрели в одни и те же папки.

### `app/settings.py`
Настройки приложения.

* `DEFAULTS` — значения по умолчанию, `READONLY` — поля, которые нельзя менять
  из интерфейса (`channel`, `disabled_voices`, `applio_path`, `cosyvoice_path`).
* `Settings` — словарь с загрузкой из `data/settings.json`, сохранением
  (`save()`) и нормализацией правок из интерфейса (`apply(data)`): приведение
  типов, ограничение диапазонов, обрезка списков и словарей.
* `SECRET_KEYS` и `MASK` — секреты (`twitch_token`, `twitch_client_id`) наружу
  не отдаются: `masked()` возвращает копию с маской, пустое значение остаётся
  пустым (интерфейс видит, задан ли секрет), а `apply()` воспринимает маску
  как «оставить как есть» — открытая и сохранённая форма настроек не затирает
  настоящий токен.
* Проверяется юнит-тестами `tools/test_settings.py` и золотым слепком
  `tools/golden_settings.json` (26 случаев нормализации).

### `app/chat_rules.py`
Правила чата — чистая функция, без побочных эффектов.

* `decide(msg, ctx)` — решает, что делать с сообщением: прочитать, пропустить
  (с причиной), выполнить команду или объявить событие Twitch.
* `Decision` — результат: вид решения, текст, стиль, подсказка голоса, причина
  пропуска, команда с аргументами, тип события и правило на него.
* `Context` — снимок состояния, который нужен для решения: настройки, время
  последней реплики зрителя, длина очереди, название награды.
* `COMMANDS` — реестр команд чата, `MOD_ONLY` — команды только для модератора.
* Проверяется таблицей «сообщение → решение» в `tools/test_chat_rules.py` и
  сверяется с золотым слепком `tools/golden_chat.json`.

### `app/speak_queue.py`
Очередь озвучки: порядок реплик, пауза, очистка, пропуск.

* Класс `SpeakQueue`: `pending`, `now`, `paused`, `gen` (номер поколения),
  события `wake` (пора взять задание) и `skip_event` (прервать текущее).
* Шов: синтез приходит готовой функцией `synthesize(job)`, события уходят
  колбэком `broadcast(event)`, готовность движка — `is_ready()`, смена
  состояния — `on_state()`. Модуль ничего не знает про модели и про HTTP.
* `App` собирает задание (id, пользователь, текст, голос, громкость) и отдаёт
  его очереди; HTTP-слой вызывает `skip/clear/pause/resume`.
* Имя файла — `speak_queue`, а не `queue`: каталог `app/` стоит первым в
  `sys.path`, и `queue.py` перекрыл бы стандартный модуль `queue`, который
  нужен `concurrent.futures` и `logging.handlers`.
* Проверяется отдельно: `tools/test_queue.py` (порядок, пауза, очистка, пропуск,
  поколения) и золотым слепком `tools/golden_queue.json`.

### `app/synthesis.py`
Синтез реплики: XTTS, RVC и CosyVoice 3, записи эмоций, стили речи.

* Класс `Synthesizer`: `synthesize(job)` -> (путь в `data/cache`, длительность).
  Это единственный шов: очередь и HTTP знают только его.
* Сотрудники передаются явно: движок, голоса, настройки, записи эмоций, мосты
  RVC и CosyVoice. Глобальных переменных нет.
* Внутри: `style_params` (стиль речи под голос), `emote_voice_audio` и
  `emote_segs` (звук эмоции голосом), `cosy_parts` и `render_cosy` (CosyVoice 3 со
  своими тегами эмоций), `synthesize` (общий путь: XTTS, RVC, смешанный текст
  для CosyVoice 3).
* Точность вычислений не меняется: модель в fp32 (ADR 0004).
* Проверяется слепками очереди и HTTP, юнит-тестом `tools/test_synthesis.py` и
  контрольным набором аудио `tools/quality_baseline.py` (8 фиксированных
  текстов, слепое A/B-прослушивание «до/после»).

### `app/engine.py`
Движок XTTS v2.

* `_setup_hf_cache()` — переносит кэш моделей HuggingFace в `models/hf` рядом с
  программой, чтобы не занимать системный диск.
* `load()` — `ModelManager().download_model()`, `Xtts.init_from_config()`,
  перенос на GPU, чтение голосов из комплекта модели.
* `make_latents()` / `load_latents()` — слепок голоса: эмбеддинг говорящего +
  conditioning из нарезанных клипов.
* `synthesize()` — генерация с подстановкой `gpt_cond_latent` и `speaker_embedding`,
  опциональным сдвигом тона (librosa `pitch_shift`).

### `app/voices.py`
Хранилище голосов — одна директория на голос в `voices/`:

```
voices/<id>/
├── clips/     нарезанные фрагменты записи
├── latents.pth слепок XTTS
├── cv_prompt.wav  образец для CosyVoice (склейка клипов до 12 с)
└── meta.json  имя, псевдонимы, движок, тон, эталон f0, транскрипт
```

* `prepare_cosyvoice()` — собирает образец для CosyVoice из клипов.
* `measure_f0()` — считает эталонную высоту тона.
* У каждого голоса есть `engine`: `xtts` или `cosy`.

### `app/cosyvoice.py` + `app/cosyvoice_worker.py`
Мост к CosyVoice 3.

* Мост находит папку модели (`cosyvoice_path` в настройках или поиском рядом
  с программой), проверяет наличие окружения, исходников и `cosyvoice3.yaml`.
* Воркер запускается **лениво**: `CosyVoiceBridge.start()` поднимает процесс,
  процесс отвечает `{"ready": true}` — и модель занимает видеопамять.
* Запрос синтеза: `{"cmd": "synthesize", "text", "prompt_wav", "prompt_text", "output", "speed"}`.
* В тексте образца обязателен маркер `You are a helpful assistant.<|endofprompt|>` —
  без него CosyVoice 3 отказывается работать с in-context (это требование модели,
  а не ошибка кода).
* `{"cmd": "transcribe", "input"}` — расшифровка образца встроенным Whisper.

### `app/rvc.py` + `app/rvc_worker.py` + `app/rvc_train.py`
RVC.

* `rvc.py` — загрузка модели и инференс через Applio, поиск папки Applio.
* `rvc_worker.py` — процесс в окружении Applio.
* `rvc_train.py` — обучение: нарезка → извлечение признаков и тона → обучение →
  сборка индекса, с прогрессом и возможностью отмены.

### `app/textproc.py`
Чистка текста перед озвучкой: убирает разметку и эмодзи, режет на фразы,
пропускает сообщения из одних цифр, команды и сообщения наград.
При включённых эмоциях находит ремарки и ставит на их место метки `{laugh}`, `{sigh}`.

### `app/langs.py`
Определение языка сообщения: по алфавиту и по частотным словам. Даёт код языка для
каждого куска текста; язык, которого нет у XTTS, переводится в ближайшего родственника
(украинский -> русский, греческий -> английский).

### `app/emote_text.py`
Разбор эмоций в тексте: словарь ремарок, метки `{laugh}`, теги CosyVoice 3,
вокализации голоса. Только текст - без звука и без файлов.

### `app/emotes.py`
Звуковая часть эмоций: записи из `sounds/<эмоция>/`, обрезка, нормализация,
кэш и вклейка в речь. Разбор ремарок лежит в `app/emote_text.py`.

### `app/textkeys.py`
Сравнение имён без регистра, пробелов и ё - ключ для голосов и папок записей.
Листовой модуль без импортов: им пользуются и голоса, и звук эмоций.

### `app/twitch.py`
Анонимное чтение чата Twitch через WebSocket. Логин и пароль не нужны.

### `app/web/*`
Интерфейс без фреймворков: `index.html` (чат), `poll.html` (опрос и озвучка),
`voices.html` (голоса, движки, обучение RVC), `overlay.html` (оверлей для OBS),
`player.html` (плеер звука отдельной страницей), `brb.html` (BRB-экран с
таймером), `style.css` — общая тема.

## Разделение `app/main.py`

`app/main.py` вырос до ~1 700 строк и менялся в 11 из 20 последних коммитов:
в нём смешались HTTP-слой, правила чата, очередь, синтез и работа с Twitch API.
Разбиение идёт по шагам, каждый шаг — отдельный коммит, поведение не меняется
(проверяется золотым слепком и набором тестов).

1. **Сделано: правила чата** → `app/chat_rules.py`. Шов: `decide(msg, ctx)`.
   App собирает снимок состояния и исполняет решение.
2. **Сделано: HTTP-слой** → `app/api.py`. Шов: `build_routes(state)`.
   Обработчики получают состояние явно; глобальных переменных нет.
   Общие пути вынесены в `app/paths.py`.
3. **Сделано: настройки** → `app/settings.py`. Шов: `Settings` и `apply(data)`.
   Класс-наследник словаря: `app_state.settings['volume']` работает как раньше,
   но загрузка, сохранение и нормализация живут в одном месте.
4. **Сделано: разрыв цикла** `textproc ↔ emotes`. Разбор ремарок уехал в
   `app/emote_text.py`, сравнение имён - в `app/textkeys.py`. Циклов в графе
   импортов больше нет, это проверяет `tools/test_imports.py`.
5. **Сделано: очередь** → `app/speak_queue.py`. Шов: класс `SpeakQueue`
   с колбэками `synthesize/broadcast/is_ready`; App собирает задание и отдаёт
   его очереди. Проверяется `tools/test_queue.py` и слепком
   `tools/golden_queue.json`.
6. **Сделано: синтез** → `app/synthesis.py`. Шов: `synthesize(job)`.
   Код перенесён дословно: тела семи функций совпадают с исходными побайтово
   (сравнение с версией до переноса). `main.py` 960 → 661 строка.
7. **После этого: скорость.** Разбиение само по себе генерацию не ускоряет.
   Замеры на RTX 5070: XTTS синтезирует примерно в реальном времени (7.9 с на
   7.8 с звука), GPU загружен на 96 %, а воркер ждёт конца звучания перед
   следующим сообщением. Рычаги: предгенерация следующего сообщения во время
   звучания текущего, пакетный синтез длинных фраз, выгрузка
   RVC/CosyVoice из видеопамяти, когда они не обучаются. Снижение точности
   (fp16, TF32, квантизация) запрещено — см. ADR 0004.
   Обязательное условие: контрольный набор `tools/quality_baseline.py`
   (8 фиксированных текстов) и слепое A/B-прослушивание до и после.

## Фронтенд

Один стек без фреймворков: статические HTML-страницы + общий CSS + vanilla JS.
Дизайн-система лежит в `app/web/style.css` (токены -> база -> компоненты -> страницы).

| Страница | Файл | Роль |
|---|---|---|
| Опрос | `poll.html` | голосование, радар зала, чат (iframe), озвучка объявлений |
| Чат | `index.html` | лента чата, подключение, очередь, настройки (модальное окно) |
| Голоса | `voices.html` | клонирование голосов, движки, обучение RVC |
| Оверлей | `overlay.html` | прозрачный чат для OBS |

Страница «Опрос» умеет работать и как отдельный файл с диска (`file://`), поэтому
внутрь неё встроена копия общих стилей. Копия синхронизируется скриптом:

```
python tools/sync_poll_css.py
```

Чат открывается внутри «Опроса» как iframe с `?embed=1` — в этом режиме
шапка скрывается, боковая панель переносится в сетку карточек (без
горизонтальной прокрутки), а заглушка «включить звук» превращается в
компактную полосу вместо полноэкранного блокиратора (`body.embed` в `style.css`).

Имена классов в `style.css` общие для всех страниц, поэтому у CSS «Опроса»
и «Голосов» есть пересечения (например, `.bar` — прогресс-бар обучения RVC
и полосы результатов опроса). Страничные правила, которые могут конфликтовать
с общими, дополнительно ограничены по префиксу (`.bars .bar`).

## Громкость и мьют

* Общая громкость — `settings.volume`, диапазон 0–200 % (в настройках хранится как
  доля 0.0–2.0).
* Своя громкость голоса — `volume` в `voices/<id>/voice.json`, диапазон 0–200 %.
  Меняется через `POST /api/voice/volume`, применяется при воспроизведении.
* Мьют озвучки — `settings.muted`. Включается кнопкой «Озвучка» в шапке (все страницы).
  При мьюте сервер не синтезирует реплики (в чате они помечаются «озвучка выключена»),
  текущая реплика и очередь сбрасываются.
* Усиление выше 100 % делает Web Audio (`GainNode`): у HTMLMediaElement
  громкость ограничена единицей. Общая громкость умножается на громкость голоса.

## Языки сообщений

* Определение языка — `app/langs.py`: алфавит (кириллица, иероглифы, кана,
  хангыль, арабский, деванагари, тайский, греческий, иврит) плюс частотные слова.
  Смешанные сообщения режутся на куски по языкам — `textproc.segments()`.
* `textproc.ALLOWED_RE` больше не выбрасывает буквы чужих алфавитов:
  раньше китайское или украинское сообщение превращалось в пустоту.
* Код языка для XTTS — `engine.XttsEngine.model_lang()`: сверяется с
  `config.languages` модели (иначе XTTS падает на ассерте), неизвестный язык
  переводится в ближайшего родственника. Если синтез на языке не прошёл — пробуется
  английский, иначе кусок пропускается.
* Японский требует `cutlet` со словарём MeCab: `engine._setup_japanese()` создаёт
  `data/mecabrc` и прописывает `FUGASHI_TAGGER_ARGS`. Китайский — пакет `pypinyin`.
* Пакеты `pypinyin cutlet unidic-lite` ставит `install.bat`.
* Выбор движка по языку: `langs.COSY_LANGS` (ru, en, zh) — языки, которые читает
  CosyVoice 3; `langs.split_by_supported()` делит куски на группы. В `main.App._synth`
  группа CosyVoice синтезируется моделью, остальное — XTTS с латантами того же голоса,
  части склеиваются паузой. Проверено: корейский на CosyVoice-голосе уходит в XTTS
  (3/3 верно), китайский остаётся в CosyVoice.
* Лишний «хвост» XTTS: `engine.too_long()` оценивает ожидаемую длительность по числу
  символов (иероглифы — 0,3 с на символ, остальные — 0,12 с на букву). Если рендер
  явно длиннее нормы, `engine.XttsEngine._infer()` повторяет синтез с другой temperature
  и оставляет более короткий вариант. Если хвост остался, `engine.trim_tail()` находит
  паузу (0,3 с тишины) и отрезает речь после неё — только для коротких фраз (до 12
  символов) на китайском, японском и корейском.
* Разбиение длинных текстов — своё (`textproc._split_long`): сначала текст делится
  на предложения (`textproc._sentences` — европейская и восточноазиатская пунктуация),
  потом предложения собираются в куски не длиннее лимита из `char_limits`
  токенизатора XTTS для каждого языка. Фраза посередине не разрывается; части без
  пробелов (китайский, японский, корейский) склеиваются без него. Встроенное разбиение
  XTTS (`enable_text_splitting`) отключено — оно тянет spacy, которого нет, и из-за
  него китайский и японский уходили в английский откат.

## Эмоции в сообщениях

* Разбор ремарок — `app/emotes.py`: `split_emotes()` режет сообщение на текст и куски-эмоции,
  `textproc.clean_text()` превращает их в метки `{laugh}`, `{sigh}`,
  а `textproc.segments()` отдаёт их отдельными кусками `("emote", "laugh")`.
* Выключатель — `settings.emotes` («Настройки» → «Эмоции»), по умолчанию включено.
* CosyVoice 3: `emotes.cosy_text()` подставляет теги модели
  (`[laughter]`, `[sigh]`, …). Воркер (`app/cosyvoice_worker.py`) проверяет `tags_survive()`:
  если нормализатор текста портит тег, для этой фразы отключается `text_frontend`.
* XTTS и RVC: `EmoteSounds.resolve()` меняет кусок-эмоцию на запись из `sounds/<эмоция>/`
  (нормировка по пику 0,7, срез тишины, обрезка до 6 с). У RVC запись идёт через модель
  вместе с речью и получает тембр персонажа.
* Если записи нет, звук эмоции генерирует сам голос: `main.emote_voice_audio()` синтезирует
  вокализацию («фх…», «ха-ха-ха…») тем же голосом, которым читается сообщение, и вклеивает
  её отдельным куском. Слово («вдох», «смех») не читается никогда. Результат кэшируется
  в `_emote_cache` по ключу (голос, эмоция); `POST /api/emotes/reset` очищает кэш.
* Куски вида `("audio", samples)` вклеиваются движком (`app/engine.py`); тон по ним не сдвигается.
* Ограничения: не больше 4 эмоций в сообщении, одинаковые подряд — один раз.

## Хранилище

* Настройки — `data/settings.json` (JSON, читается при старте, пишется при изменении).
* Голоса — `voices/<id>/meta.json` + слепки.
* Кэш озвучки — `data/cache/*.wav`, отдаётся по `/audio/<имя>`.
* Записи эмоций — `sounds/<эмоция>/` (создаётся при первом запуске, в репозиторий не входит).
* Логи — `data/log.txt`, `data/cosyvoice_log.txt`, `data/rvc_log.txt`.

## Поток одного сообщения

```
сообщение в чате
  -> textproc: чистка, отсев цифр/команд
  -> проверки: пауза зрителя, очередь, аудитория
  -> выбор голоса (свою реплику / по умолчанию / случайный)
  -> движка: XTTS (поток) | RVC (процесс) | CosyVoice 3 (процесс)
  -> wav в data/cache
  -> воспроизведение вкладкой браузера
```
