# Архитектура TwitchTTS

Краткая карта модулей, процессов и потоков данных.

```
        браузер / OBS
              |  HTTP + WebAudio
              v
     +------------------------+
     |  app/main.py (Starlette)|  порт 8765
     |  - /api/state, /api/*   |
     |  - очередь озвучки      |
     |  - пул потоков синтеза  |
     +---+--------+--------+----+
         |        |        |
   XTTS  |   RVC  |   CosyVoice 3
   поток |  поток |   отдельный процесс
         |        |
   app/engine.py  app/rvc.py      app/cosyvoice.py
         |        |        |
    TTS v2   Applio    app/cosyvoice_worker.py
   (venv)    (env)     (окружение CosyVoice)
```

## Процессы

| Процесс | Где живёт | Как общается |
|---|---|---|
| Основной сервер | `venv/Scripts/python.exe app/main.py` | HTTP |
| RVC-воркер | `Applio/env/python.exe app/rvc_worker.py` | построчно через stdin/stdout, префикс `@@RVC@@` |
| CosyVoice-воркер | `cosyvoice/env/python.exe app/cosyvoice_worker.py` | построчно через stdin/stdout, префикс `@@CV@@` |
| Обучение RVC | внутри Applio | отдельный процесс, прогресс читается из лога |

Воркеры живут в **своих** окружениях: у XTTS, RVC и CosyVoice несовместимые наборы
зависимостей и версии PyTorch. Поэтому общение с ними — простой текстовый протокол
(одна строка JSON на запрос, одна строка JSON на ответ), а не импорт через Python API.

XTTS — единственный движок, который импортируется напрямую (`app/engine.py`),
поэтому он выполняется в пуле потоков основного процесса.

## Модули

### `app/main.py`
Сервер и оркестратор.

* Маршруты: `/` (главная), `/poll`, `/voices`, `/overlay`, `/audio/*`, `/api/*`.
* `/api/state` — сводка: статусы движков, настройки, список голосов, очередь.
* `/api/preview` — озвучка тестовой фразы выбранным голосом.
* `/api/voice/engine` — переключение XTTS / CosyVoice 3 у конкретного голоса.
* `/api/cosyvoice/setup` — ленивый запуск движка CosyVoice 3.
* `/api/voice/transcript` — текст образца для CosyVoice (правится вручную).
* `_synth()` — общий путь синтеза: очистка текста → выбор движка → озвучка →
  запись файла в `data/cache` → отдача по `/audio`.
* Очередь озвучки с лимитом, паузой между репликами одного зрителя и
  «только подписчики».

### `app/engine.py`
Движок XTTS v2.

* `_setup_hf_cache()` — переносит кэш моделей HuggingFace в `models/hf` рядом с
  программой, чтобы не занимать системный диск.
* `load()` — `ModelManager().download_model()`, `Xtts.init_from_config()`,
  перенос на GPU, чтение голосов из комплекта модели.
* `make_latents()` / `load_latents()` — слепок голоса: эмбеддинг говорящего +
  conditioning из нарезанных клипов.
* `synthesize()` — генерация с подстановкой `gpt_cond_latent` и `speaker_embedding`,
  опциональным сдвигом тона (librosa `pitch_shift`).

### `app/voices.py`
Хранилище голосов — одна директория на голос в `voices/`:

```
voices/<id>/
├── clips/     нарезанные фрагменты записи
├── latents.pth слепок XTTS
├── cv_prompt.wav  образец для CosyVoice (склейка клипов до 12 с)
└── meta.json  имя, псевдонимы, движок, тон, эталон f0, транскрипт
```

* `prepare_cosyvoice()` — собирает образец для CosyVoice из клипов.
* `measure_f0()` — считает эталонную высоту тона.
* У каждого голоса есть `engine`: `xtts` или `cosy`.

### `app/cosyvoice.py` + `app/cosyvoice_worker.py`
Мост к CosyVoice 3.

* Мост находит папку модели (`cosyvoice_path` в настройках или поиском рядом
  с программой), проверяет наличие окружения, исходников и `cosyvoice3.yaml`.
* Воркер запускается **лениво**: `CosyVoiceBridge.start()` поднимает процесс,
  процесс отвечает `{"ready": true}` — и модель занимает видеопамять.
* Запрос синтеза: `{"cmd": "synthesize", "text", "prompt_wav", "prompt_text", "output", "speed"}`.
* В тексте образца обязателен маркер `You are a helpful assistant.<|endofprompt|>` —
  без него CosyVoice 3 отказывается работать с in-context (это требование модели,
  а не ошибка кода).
* `{"cmd": "transcribe", "input"}` — расшифровка образца встроенным Whisper.

### `app/rvc.py` + `app/rvc_worker.py` + `app/rvc_train.py`
RVC.

* `rvc.py` — загрузка модели и инференс через Applio, поиск папки Applio.
* `rvc_worker.py` — процесс в окружении Applio.
* `rvc_train.py` — обучение: нарезка → извлечение признаков и тона → обучение →
  сборка индекса, с прогрессом и возможностью отмены.

### `app/textproc.py`
Чистка текста перед озвучкой: убирает разметку и эмодзи, режет на фразы,
пропускает сообщения из одних цифр, команды и сообщения наград.
При включённых эмоциях находит ремарки и ставит на их место метки `{laugh}`, `{sigh}`.

### `app/emotes.py`
Эмоции в сообщениях: словарь ремарок, разбор сообщения на текст и эмоции,
теги CosyVoice 3, записи из `sounds/<эмоция>/` и вокализации, которые генерирует голос.

### `app/twitch.py`
Анонимное чтение чата Twitch через WebSocket. Логин и пароль не нужны.

### `app/web/*`
Интерфейс без фреймворков: `index.html` (чат), `poll.html` (опрос и озвучка),
`voices.html` (голоса, движки, обучение RVC), `overlay.html` (оверлей для OBS),
`style.css` — общая тема.

## Фронтенд

Один стек без фреймворков: статические HTML-страницы + общий CSS + vanilla JS.
Дизайн-система лежит в `app/web/style.css` (токены -> база -> компоненты -> страницы).

| Страница | Файл | Роль |
|---|---|---|
| Опрос | `poll.html` | голосование, радар зала, чат (iframe), озвучка объявлений |
| Чат | `index.html` | лента чата, подключение, очередь, настройки (модальное окно) |
| Голоса | `voices.html` | клонирование голосов, движки, обучение RVC |
| Оверлей | `overlay.html` | прозрачный чат для OBS |

Страница «Опрос» умеет работать и как отдельный файл с диска (`file://`), поэтому
внутрь неё встроена копия общих стилей. Копия синхронизируется скриптом:

```
python tools/sync_poll_css.py
```

Чат открывается внутри «Опроса» как iframe с `?embed=1` — в этом режиме
шапка скрывается, боковая панель переносится в сетку карточек (без
горизонтальной прокрутки), а заглушка «включить звук» превращается в
компактную полосу вместо полноэкранного блокиратора (`body.embed` в `style.css`).

Имена классов в `style.css` общие для всех страниц, поэтому у CSS «Опроса»
и «Голосов» есть пересечения (например, `.bar` — прогресс-бар обучения RVC
и полосы результатов опроса). Страничные правила, которые могут конфликтовать
с общими, дополнительно ограничены по префиксу (`.bars .bar`).

## Громкость и мьют

* Общая громкость — `settings.volume`, диапазон 0–200 % (в настройках хранится как
  доля 0.0–2.0).
* Своя громкость голоса — `volume` в `voices/<id>/voice.json`, диапазон 0–200 %.
  Меняется через `POST /api/voice/volume`, применяется при воспроизведении.
* Мьют озвучки — `settings.muted`. Включается кнопкой «Озвучка» в шапке (все страницы).
  При мьюте сервер не синтезирует реплики (в чате они помечаются «озвучка выключена»),
  текущая реплика и очередь сбрасываются.
* Усиление выше 100 % делает Web Audio (`GainNode`): у HTMLMediaElement
  громкость ограничена единицей. Общая громкость умножается на громкость голоса.

## Эмоции в сообщениях

* Разбор ремарок — `app/emotes.py`: `split_emotes()` режет сообщение на текст и куски-эмоции,
  `textproc.clean_text()` превращает их в метки `{laugh}`, `{sigh}`,
  а `textproc.segments()` отдаёт их отдельными кусками `("emote", "laugh")`.
* Выключатель — `settings.emotes` («Настройки» → «Эмоции»), по умолчанию включено.
* CosyVoice 3: `emotes.cosy_text()` подставляет теги модели
  (`[laughter]`, `[sigh]`, …). Воркер (`app/cosyvoice_worker.py`) проверяет `tags_survive()`:
  если нормализатор текста портит тег, для этой фразы отключается `text_frontend`.
* XTTS и RVC: `EmoteSounds.resolve()` меняет кусок-эмоцию на запись из `sounds/<эмоция>/`
  (нормировка по пику 0,7, срез тишины, обрезка до 6 с). У RVC запись идёт через модель
  вместе с речью и получает тембр персонажа.
* Если записи нет, звук эмоции генерирует сам голос: `main.emote_voice_audio()` синтезирует
  вокализацию («фх…», «ха-ха-ха…») тем же голосом, которым читается сообщение, и вклеивает
  её отдельным куском. Слово («вдох», «смех») не читается никогда. Результат кэшируется
  в `_emote_cache` по ключу (голос, эмоция); `POST /api/emotes/reset` очищает кэш.
* Куски вида `("audio", samples)` вклеиваются движком (`app/engine.py`); тон по ним не сдвигается.
* Ограничения: не больше 4 эмоций в сообщении, одинаковые подряд — один раз.

## Хранилище

* Настройки — `data/settings.json` (JSON, читается при старте, пишется при изменении).
* Голоса — `voices/<id>/meta.json` + слепки.
* Кэш озвучки — `data/cache/*.wav`, отдаётся по `/audio/<имя>`.
* Записи эмоций — `sounds/<эмоция>/` (создаётся при первом запуске, в репозиторий не входит).
* Логи — `data/log.txt`, `data/cosyvoice_log.txt`, `data/rvc_log.txt`.

## Поток одного сообщения

```
сообщение в чате
  -> textproc: чистка, отсев цифр/команд
  -> проверки: пауза зрителя, очередь, аудитория
  -> выбор голоса (свою реплику / по умолчанию / случайный)
  -> движка: XTTS (поток) | RVC (процесс) | CosyVoice 3 (процесс)
  -> wav в data/cache
  -> воспроизведение вкладкой браузера
```
